# When2Meet

주별 고정 일정을 제외하고 링크로 가능한 시간을 모으는 한국어 일정 조율 서비스입니다. 시간은 한국 표준시이며 30분 단위입니다.

약속의 전체 참여 현황에서 저장된 참여 가능 인원을 색 농도와 숫자로 확인할 수 있습니다. ‘가장 많이 가능’은 약속 전체 기간에서 최대 인원이 가능한 칸을 강조하며, 모두 가능한 시간이 있으면 해당 칸이 강조됩니다. 응답이 없거나 모두 빈 응답이면 가능한 시간으로 표시하지 않습니다. 시간칸을 클릭하거나 방향키와 Enter/Space로 선택하면 가능한 사람과 선택하지 않은 사람을 구분해 보여주며, 결과 조회는 편집 중인 내 응답을 변경하지 않습니다. ‘결과 새로고침’ 후에도 선택한 필터와 상세 시간은 유지됩니다.

내 가능 시간표의 날짜 제목을 누르면 해당 날짜의 고정 일정 제외 시간을 모두 선택하고, 다시 누르면 그 날짜만 해제합니다. 일부만 선택된 날짜는 나머지 가능 시간을 채웁니다. 다른 날짜의 선택은 그대로 유지하며, 선택 가능한 시간이 전부 고정 일정이면 날짜 버튼을 비활성화합니다. 변경한 응답은 자동으로 저장합니다. Ctrl+Z 또는 Cmd+Z와 ‘되돌리기’ 버튼으로 이전 선택을 복원하며, 복원한 내용도 자동 저장합니다. 드래그 한 번이나 날짜 전체 선택 한 번을 각각 하나의 변경으로 취급합니다. 입력란에서는 기본 텍스트 되돌리기를 유지합니다. 되돌리기 기록은 현재 페이지에서만 유지됩니다.

약속 길이는 지정하지 않습니다. 가능한 참여자가 동일한 연속된 시간을 묶어 보여주며, 예전 약속에 저장된 길이도 결과를 제한하지 않습니다. 기존 데이터와 이전 버전의 호환성을 위해 데이터베이스의 `duration` 열은 유지하지만 새 약속에는 사용하지 않는 값 0을 저장합니다.

‘일정 저장’은 현재 이벤트에 작성한 선택을 이름과 함께 계정에 보관합니다. 계정당 최대 30개이며 다른 기기에서도 조회할 수 있습니다. 원본 이벤트를 삭제해도 저장 일정은 유지됩니다. ‘불러오기’는 같은 날짜와 서로 겹치는 시간 범위만 교체하고 나머지 선택은 유지합니다. 빈 선택도 그대로 복원하며 현재 고정 일정은 제외합니다. 날짜를 요일에 맞춰 이동하지 않습니다. 불러온 결과는 자동 저장되며 Ctrl+Z / Cmd+Z 한 번으로 되돌릴 수 있습니다. 보관함에서 더 이상 쓰지 않는 저장 일정을 삭제할 수 있습니다.

전체 참여 현황의 ‘이미지 저장’은 현재 결과 필터를 반영한 PNG를 만듭니다. 스크롤로 가려진 날짜와 시간도 모두 포함합니다. ‘엑셀 저장’은 숫자와 날짜를 실제 값으로 기록한 전체 현황과 참여자별 연속 가능 시간, 빈 응답을 두 시트로 내보냅니다. 종료 24:00도 유지합니다. 이름과 제목은 수식으로 실행되지 않는 문자열이며, 고정 일정 이름·내용이나 이메일은 내보내지 않습니다. 내 응답 저장이 실패하면 오래된 응답을 내보내지 않고 먼저 저장 상태를 확인하도록 안내합니다. XLSX 생성기는 내려받을 때만 불러옵니다.

시간표는 최대 14일 전체를 나란히 표시합니다. 가로세로 드래그한 사각 영역을 칠하거나 지울 수 있고 고정 일정은 항상 건너뜁니다. 모바일에서는 기본적으로 스크롤과 탭을 사용하고, ‘드래그로 칠하기’를 켜면 손가락으로 영역을 선택합니다. 가장자리에서는 시간표가 자동으로 스크롤됩니다. 방향키와 Space 선택도 지원합니다.

고정 일정도 일요일부터 토요일까지 주간 시간표에서 칠할 수 있습니다. 칠한 영역에 이름을 입력해 저장하면 요일별 연속 블록으로 등록됩니다. 저장된 일정은 각 블록의 중앙에 이름을 한 번 표시하고 서로 다른 색을 배정합니다. 색은 새로고침 후에도 유지되며, 시간이 겹치는 기존 일정은 나란히 표시합니다. 기존 일정과 겹치는 칸은 새로 칠하지 않습니다. 에브리타임 링크는 모바일 앱의 시간표 탭에서 우측 상단 톱니바퀴 아이콘을 누른 뒤 ‘링크 공유’로 복사할 수 있습니다.

고정 일정 탭에서 새로 칠하거나 직접 입력하는 시간은 09:00~24:00입니다. 시간표 우측 상단의 돋보기로 행 높이를 줄여 축소하거나 원래 크기로 되돌릴 수 있으며, 선택과 블록 색은 그대로 유지됩니다. 09:00 이전에 저장되었거나 가져온 기존 일정은 삭제하지 않으며 아래 목록과 약속 제외 계산에서 계속 유지합니다.

## 실행

Node.js 24 이상을 권장합니다. `npm ci`로 의존성을 설치한 뒤 `npm run dev`를 실행하고 http://127.0.0.1:4173 을 엽니다. 계정과 일정 데이터는 `.local/when2meet.sqlite`에 저장됩니다. `npm test`는 인증, 일정 계산과 API 보호 동작을, `npm run build`는 기존 Worker 호환 빌드를 검증합니다.

## 에브리타임 시간표 가져오기

‘내 고정 일정’에서 에브리타임 시간표의 공개 ‘URL 공유’ 링크를 입력하면 수업을 미리 볼 수 있습니다. 선택한 수업만 기존 고정 일정에 추가하며, 이름·요일·시간이 같은 일정은 중복으로 추가하지 않습니다. 시간 미지정 수업은 제외하고 개수를 안내합니다. 수업 시간이 30분 경계에 맞지 않으면 겹치는 30분 칸 전체를 차단합니다. 가져온 후에도 기존 일정은 유지됩니다. 자동 동기화는 하지 않으므로 시간표를 변경했다면 기존 항목을 정리한 뒤 다시 가져와야 합니다.

에브리타임 로그인 정보는 수집하지 않습니다. 로그인한 When2Meet 사용자만 가져오기를 요청할 수 있고, 서버는 에브리타임의 고정된 공개 시간표 주소로만 요청합니다. 공유 링크가 비공개이거나 에브리타임의 비공식 응답 형식이 변경되면 가져오기가 실패할 수 있습니다. ‘고정 일정 제외 모두 선택’은 약속의 전체 기간에서 고정 일정과 겹치지 않는 칸만 선택하며 자동으로 저장됩니다.

## 회원과 공유

자체 Node 서버에서는 이름·이메일·비밀번호로 가입하면 바로 로그인됩니다. 이메일 인증이나 메일 발송 서비스는 필요하지 않습니다. 비밀번호는 8~128자이며 무작위 솔트와 scrypt(N=32768, r=8, p=3)로 해시합니다. 로그인 세션은 무작위 토큰의 해시만 서버에 저장하고, 브라우저에는 HttpOnly·SameSite=Lax 쿠키를 사용합니다. HTTPS 운영에서는 Secure와 __Host- 접두사도 적용됩니다. 계정과 접속 주소별 시도 제한, 동시 해시 처리 제한, 출처 검사도 적용합니다.

이메일 주소는 소유 여부를 검증하지 않는 로그인 식별자입니다. 이메일을 통한 비밀번호 재설정이나 계정 복구는 제공하지 않습니다. 기존 ChatGPT 계정과 이메일이 같더라도 자동으로 계정을 연결하거나 기존 일정의 소유권을 넘기지 않습니다.

생성된 `/m/<id>` 링크는 같은 서버의 저장된 약속을 엽니다. 참여자는 자체 회원가입이나 로그인 후 응답할 수 있습니다. 기존 ChatGPT Sites 배포본은 별도 서비스이며, 자체 계정의 공개 서버로 사용할 수 없습니다.

고정 일정의 이름과 시간은 계정 소유자만 조회합니다. 약속 링크를 가진 로그인 사용자는 약속 제목, 날짜, 참여자 표시 이름, 각자가 제출한 가능 시간과 전체 집계를 볼 수 있습니다. 참여자를 선택하면 약속 전체 기간의 날짜를 가로로 나란히 표시한 표에서 30분 단위의 가능 시간을 한 번에 확인할 수 있습니다. 사람을 바꾸어 비교할 수 있고, 동명이인은 번호로 구분합니다. 새 고정 일정은 이미 제출한 응답 집계에서도 제외되며, 삭제된 고정 일정의 시간은 참여자가 다시 선택해 제출해야 합니다.

수정 요청은 서버에서 본인 계정으로 제한하고, 다른 사이트에서의 쓰기 요청을 차단합니다. 고정 일정과 응답은 버전 확인으로 다른 창의 변경 사항을 덮어쓰지 않습니다. 자동 저장 중에도 선택을 계속할 수 있고 요청을 순서대로 처리합니다. 연결 오류가 나면 선택을 유지하고 ‘다시 저장’을 표시하며, 연결 복구 시 재시도합니다. 다른 창의 변경과 충돌하면 자동 저장을 멈추고 저장된 응답을 명시적으로 다시 불러오도록 안내합니다. 시간 선택이 저장되지 않은 상태에서 나가면 브라우저가 확인을 요청합니다.

## 검사

`tests/browser.mjs`는 Puppeteer Core와 Chrome 경로를 환경 변수로 전달해 실행합니다. 두 자체 계정으로 이메일 인증 없는 가입, 생성한 링크 접속, 참여 저장, 반복 일정 변경, 키보드 선택, 모바일 화면을 검사합니다. `tests/auth.test.mjs`는 중복 이메일, 비밀번호 해시, 세션 만료·폐기, 시도 제한, 출처 검사와 외부 인증 헤더 위조 차단을 검사합니다.

## 배포

### GitHub Pages

공개 주소: https://0verhydrated.github.io/when2meet/

#### Supabase 연결

Supabase 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 실행한 뒤 `supabase/migrations/`의 파일을 이름순으로 실행합니다. Authentication 설정에서 이메일 가입을 허용하고 이메일 확인을 끕니다. 비밀번호 최소 길이는 8자로 지정합니다. Site URL은 위 공개 주소로 설정합니다.

기존 Supabase 프로젝트에는 `supabase/migrations/202611230001_participant_availability.sql`을 실행해 참여자별 가능 시간 조회를 추가합니다. 계정·일정·응답 데이터는 유지하며 조회 함수만 교체합니다. 시간표 양쪽 끝에는 30분 간격의 시간과 마지막 종료 시각을 표시합니다.

`supabase/migrations/202611240001_meeting_deletion.sql`은 삭제 비밀번호와 삭제 상태를 추가합니다. 먼저 서버에 적용한 뒤 프런트엔드를 배포합니다. 기존 일정 데이터는 유지합니다. 새 약속은 8~128자의 삭제 비밀번호가 필수이며, 기존 약속은 만든 사람이 삭제 창에서 비밀번호를 한 번 설정할 수 있습니다. 만든 사람만 비밀번호를 확인한 뒤 삭제할 수 있으며 기존 비밀번호를 덮어쓸 수 없습니다. 삭제는 목록과 모든 참여·조회 경로를 차단하는 논리 삭제이며, 원본 행과 응답은 관리자 복구를 위해 남깁니다.

`supabase/migrations/202611280001_saved_schedules.sql`을 이어서 실행하면 계정별 보관함을 추가합니다. 본인만 RPC로 조회·저장·삭제할 수 있고 테이블에 직접 접근할 수 없습니다. 원본 이벤트 범위와 현재 고정 일정을 서버에서 다시 검사하며, 계정 행 잠금으로 동시에 저장하더라도 보관 한도를 지킵니다. 기존 계정·이벤트·응답과 삭제 비밀번호를 보존합니다. 로컬 서버는 `0003_saved_schedules`를 자동 적용합니다.

삭제 비밀번호는 SHA-256으로 길이를 고정한 뒤 무작위 솔트를 쓰는 bcrypt(비용 10)로 저장합니다. 긴 한국어 비밀번호도 잘리지 않으며 해시는 API로 반환하지 않습니다. 15분 동안 5번 틀리면 같은 약속의 삭제 시도를 제한합니다. Supabase에서는 원래 일정 RPC를 권한이 없는 비공개 함수로 옮기고 삭제 검사를 통과한 요청만 전달합니다. 결과 아래의 추천 시간 목록과 초기 상세 안내는 표시하지 않으며, 시간칸을 선택했을 때 해당 참여자의 가능 여부는 계속 조회할 수 있습니다.

GitHub 저장소의 Actions 변수에 `SUPABASE_URL`과 `SUPABASE_PUBLISHABLE_KEY`를 추가하면 전체 앱이 Pages 안에서 실행됩니다. 프로젝트의 공개 publishable 키 또는 anon 키만 사용합니다. 데이터베이스 비밀번호, secret 키, service_role 키는 절대로 소스나 브라우저에 넣지 않습니다. 빌드는 비공개 키를 거부합니다.

비밀번호와 세션 관리는 Supabase Auth가 담당합니다. 프로필은 본인만 직접 읽을 수 있으며, 약속 데이터는 로그인한 사용자에게만 허용된 RPC로 처리합니다. 고정 일정의 원본 내용과 계정 이메일은 반환하지 않습니다. 참여 이름과 해당 약속에 제출한 가능 시간에서 현재의 고정 일정을 제외한 시간, 전체 집계를 반환합니다. 수정 버전 검사와 고정 일정 자동 제외는 데이터베이스에서도 강제합니다. `tests/supabase.test.mjs`는 PostgreSQL 엔진으로 접근 제한과 일정 집계를 검사합니다.

Supabase 설정이 있으면 아래의 별도 Node 서버나 `PUBLIC_SERVICE_ORIGIN`은 필요하지 않습니다. `/when2meet/?view=app`과 `/when2meet/?meeting=<id>` 형식의 주소로 가입과 약속 링크를 공유합니다.

시간표 가져오기는 별도의 Supabase Edge Function으로 실행합니다. `node scripts/build-everytime-function.mjs`로 만든 `.local/import-everytime/index.ts`를 Supabase Functions 편집기에 입력하고 `import-everytime`으로 배포합니다. 원본은 `supabase/functions/import-everytime/index.ts`와 공통 변환기 `worker/everytime.js`에 있습니다. 함수는 JWT로 사용자 신원을 확인한 뒤 공개 시간표만 읽고 데이터베이스에는 쓰지 않습니다. 미리보기에서 사용자가 추가를 누르면 기존 고정 일정 저장 API가 버전·개수·소유자를 다시 검사합니다.

`main`에 소스를 올리면 `.github/workflows/pages.yml`이 테스트와 `npm run build:pages`를 실행하고 `pages-dist/`를 배포합니다. 별도의 패키지 설치나 배포용 비밀키는 필요하지 않습니다. 저장소 변수 `PUBLIC_SERVICE_ORIGIN`에 자체 서버의 HTTPS 원점(예: `https://when2meet.example`)을 지정하면 가입과 일정 기능이 해당 서버로 연결됩니다.

GitHub Pages는 계정 정보를 저장하거나 인증 API를 실행할 수 없습니다. 자체 서버가 설정되지 않으면 ChatGPT로 이동하지 않고 가입·로그인 화면에 서버 미연결 상태를 표시합니다. 이 상태에서는 입력과 제출을 비활성화하며 계정을 만들었다고 표시하거나 비밀번호를 브라우저 저장소에 보관하지 않습니다. 실제 회원가입을 받으려면 아래 서버 배포가 필요합니다.

### 자체 회원가입 서버

HTTPS와 영구 저장 공간을 제공하는 Node 또는 Docker 호스팅에 배포합니다. SQLite 파일이 유지되지 않는 일반 서버리스 임시 파일 시스템에는 배포하지 않습니다. 환경 변수는 `.env.example`을 참고하며 Node에 직접 전달합니다.

```
NODE_ENV=production PUBLIC_ORIGIN=https://your-when2meet-server.example DATABASE_PATH=/data/when2meet.sqlite PORT=3000 npm start
```

Docker에서는 `docker build -t when2meet .`로 빌드하고 `/data`에 영구 볼륨을 연결합니다. HTTPS 종료는 호스팅의 프록시에서 처리하며 `PUBLIC_ORIGIN`은 사용자가 실제로 접속하는 정확한 HTTPS 원점이어야 합니다. 서버 시작 시 기존 데이터를 유지하면서 아직 적용되지 않은 마이그레이션만 트랜잭션으로 적용합니다. 운영자는 데이터 파일을 백업해야 합니다.

### 기존 서버

`.openai/hosting.json`의 `DB` D1 바인딩과 `drizzle/` 마이그레이션을 포함해 배포합니다. `npm run build`는 정적 파일을 포함한 `dist/server/index.js`를 생성합니다. 서버 실행 중 테이블을 생성하거나 변경하지 않습니다.
